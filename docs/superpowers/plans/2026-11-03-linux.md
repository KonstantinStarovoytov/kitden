# Kitden on Linux Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kitden installs, reads the three clients and changes their settings on a Linux desktop as it does on a Mac, with secrets in the desktop keyring.

**Architecture:** One new module, `kitden/system.py`, answers where this system keeps things; every macOS path in the code and the tests goes through it. `local_gateway/keychain.py` keeps its functions and references, runs `secret-tool` on Linux, and its runner carries stderr so "not there" and "could not reach" stay apart. The page learns the store's name ("Keychain" or "keyring") from `/api/about`. The installer accepts Linux and installs from PyPI; CI runs the suite on Ubuntu too.

**Tech Stack:** Python 3.13, Starlette, pytest, `secret-tool` (libsecret-tools), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-03-linux-design.md`

## Global Constraints

- Code, comments, UI text and docs in simple English; talk to the owner in Russian (AGENTS.md).
- Every client file change stays preview → Apply with a backup → verify → Undo. Nothing here adds a new way to write a client file.
- A secret never goes to a plain file, never on a command line, never in a log or an error text.
- Tests use sandbox homes and never run the real `security` or `secret-tool`.
- No `if sys.platform` in tests; tests go through `kitden.system`.
- `KITDEN_SYSTEM` overrides the detected system for tests and the demo only; values `mac` and `linux`.
- The reference in `gateway.json` stays `{"keychain": "<server>/<key>"}` on both systems.
- Tools by full path: `/usr/bin/security`, `/usr/bin/secret-tool`; `KITDEN_SECURITY` and `KITDEN_SECRET_TOOL` point tests at stand-ins.
- Timeout for the secret tool: 20 s on both systems.
- Facts about other tools carry the date they were checked.
- Before each commit: `uv run pytest -q`, `uv run ruff check .`, `node --test tests/frontend/*.test.mjs`.
- Commit messages: a short plain subject, one to three simple lines.

## Review Focus

1. A keyring daemon that is not running must leave the server waiting in preview with the keyring sentence, not pass preview and fail Apply. (Task 4 pins it: `secret-tool` exits 1 with a stderr line.)
2. A `lookup` that exits 1 with empty stdout and empty stderr is "not there", so Undo of a new item stays quiet and `access_rows` says "missing". (Task 4.)
3. `XDG_DATA_HOME` set in the person's shell must move the data folder; a test home must not leak into the real `~/.local/share`. (Task 1: `data_dir` reads the variable; `conftest.py` clears it.)
4. A gateway started without `DBUS_SESSION_BUS_ADDRESS` (Codex) must still reach the keyring: the environment given to `secret-tool` holds `unix:path=<XDG_RUNTIME_DIR>/bus`, or `/run/user/<uid>/bus`. (Task 4 pins the env; the Ubuntu CI round trip of Task 7 runs with a cleared environment.)
5. On an unsupported system `kitden` must stop with one sentence before touching the data folder. (Task 2.)

**Interfaces:**
- `keychain.secret_tool_path() -> str` — `KITDEN_SECRET_TOOL` or `/usr/bin/secret-tool`.
- `keychain.tool_env() -> dict[str, str]` — a copy of `os.environ`; on Linux, with `DBUS_SESSION_BUS_ADDRESS` set to `unix:path=<XDG_RUNTIME_DIR>/bus`, or `unix:path=/run/user/<os.getuid()>/bus`, when it is missing.
- `keychain.run_security` keeps its name (the call sites use it) and runs the tool of `SYSTEM`.
- Command lines (Linux): store `["store", "--label=Kitden: <account>", "service", "kitden", "account", "<account>"]` with the value on stdin and no newline; read `["lookup", "service", "kitden", "account", "<account>"]`; delete `["clear", "service", "kitden", "account", "<account>"]`.
- Rules (Linux): `read` → exit 0: the value; exit 1, empty stdout, empty stderr: `None`; anything else: `KeychainError(REACH)`. `store` → read back must equal the value, else `KeychainError(REACH)`. `delete` → exit 0, or exit 1 with empty stderr: quiet; else `KeychainError(REACH)`.
- `REACH` on Linux: `"Kitden could not reach the keyring. Install libsecret-tools and sign in to your desktop session."`; on macOS unchanged.
- The engine's and views' sentences take `secret_store_name()`: "in your keyring keeps the new value.", "stays in your keyring.", "Kitden could not reach the keyring; nothing was changed."
