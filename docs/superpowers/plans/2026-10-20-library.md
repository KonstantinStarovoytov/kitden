# Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One page, Library, replaces Load map and Discover: columns only for found clients, an
action in each client's cell, "Add skills" across clients, a "−" to hide a column, categories as
a filter and quiet row text.

**Architecture:** A new read model `views/library.py` joins the load map (what is on this Mac)
with the plugin and skill catalogs (what can be added) into one row list with per-client cells
that already say the action. `/api/library` filters it on the server (tab, show, search,
category, hidden columns, attention). A new `library.js` draws it; offer Details and add forms
move from `discover.js` to `offer.js`; `map.js` and `discover.js` go away.

**Tech Stack:** Python 3 / Starlette, plain ES modules, pytest, node:test.

**Spec:** docs/superpowers/specs/2026-10-20-library-design.md

## Global Constraints

- Every change to a client: preview → Apply with a backup → verify → Undo. "Add skills" too.
- Main page: name, client, action. Paths, addresses and commands stay in Details.
- UI text, code, comments and docs in simple English, short and plain.
- Tests use sandbox homes (`tests/conftest.py: make_home`), never the real home folder.
- Before each commit: `uv run pytest -q`, `uv run ruff check .`,
  `node --test tests/frontend/*.test.mjs`. All green.
- Commit messages: a short plain subject, one to three simple lines, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Client ids and order: `("claude_code", "codex", "cursor")`; names "Claude Code", "Codex",
  "Cursor".
- Look and motion follow docs/design.md (tokens, motion, 24 px targets, focus kept through
  redraws via `data-focus`).
- Never commit `.specify/`, `.impeccable/`, `docs/research/`, `docs/superpowers/`.

## Review Focus

1. A home where only one client is found: one column, no "−", every row still has a cell.
2. A Cursor plugin with two version folders: skills come from the newest one only, once.
3. "Add skills" when the client already has some of the plugin's skills: those are skipped, the
   rest copied, and Undo removes only what was copied.
4. Same plugin name from two marketplaces in one client: two rows, both flagged "loads it
   twice", each Details shows only its own definitions.
5. Search with "On this Mac" that matches only marketplace items: an empty table is not shown
   alone; the "N more not on this Mac · Show all" line is.

Tests for these are in Tasks 1, 2, 3, 4 and 5.

### Task 4: Library read model and API

**Files:**
- Create: `src/kitden/views/library.py`
- Modify: `src/kitden/web/app.py` (routes `/api/library`, `/api/offer`)
- Test: `tests/unit/test_library.py` (new), `tests/unit/test_api_views.py`

**Interfaces:**
- Consumes: `load_map`, `row_key`, `Row.source/lookup` (Task 1); `skill_catalog` with Cursor
  rows and categories (Task 2); `catalog`, `search`; `CursorAdapter.imports_claude_plugins()`.
- Produces: `library(inventory, adapters, project: str | None, *, gateway_registered: bool,
  kind: str, show: str = "mine", q: str = "", category: str = "",
  hidden: frozenset[str] = frozenset(), attention: bool = False) -> dict`:

```
{"columns": [{"id", "name", "mark", "hidden": bool}],   # found clients only, COLUMNS order
 "counts": {kind: int for the five kinds},             # current show, q, hidden; no category
 "rows": [row],
 "more": int,        # rows matching q that `show` hides; 0 without q
 "attention": int,   # rows on this tab with a warning flag, before the attention filter
 "categories": [{"name", "count"}],                    # plugin and skill tabs; [] otherwise
 "notes": [str]}     # marketplace lines for shown rows
row = {"key", "kind", "name", "source", "same_name": bool, "category", "description",
       "mine": bool, "lookup": str | None, "offer": str | None, "flags": [...],
       "cells": {client: {"state", "where", "items", "word", "add", "reason"}}}
add = None | {"action": "plugin.install" | "skill.install" | "plugin.skills",
              "label": "+ Add" | "Add skills" | "Add the plugin",
              "plugin": str | None, "skill": str | None, "marketplace": str | None,
              "warn": str | None}
```

- Kinds: `"mcp_server", "plugin", "skill", "hook", "marketplace"`. Show: `"mine"` (On this
  Mac), `"new"` (Can add), `"all"`; ignored (always mine) on the three tabs without a catalog.
- Rows: plugin tab = load map plugin rows ∪ catalog offers, joined on `_hash("plugin",
  offer["id"])`. Skill tab = skill catalog rows, plus load map skill rows whose name no catalog
  row has; a load map row's flags go to every catalog row with its name. Other tabs = load map
  rows. `mine` = any client has it (a load map cell other than "none", or `installed`).
- A cell from the load map keeps its `state/where/items`. Otherwise, for plugins, in order:
  1. route for this client → `add` "+ Add" (`plugin.install`; `marketplace` set when the route
     is `add_marketplace`);
  2. Cursor, `imports_claude_plugins()`, and Claude Code has a route or the plugin →
     state `"via"`, word "Via Claude Code", reason "Cursor loads Claude Code's plugins. Add it
     to Claude Code.";
  3. a skill row of this plugin is self-contained, routable here and not installed here →
     `add` "Add skills" (`plugin.skills`);
  4. it has self-contained skills and this client has them all → state `"done"`, word "Skills
     added";
  5. else state `"none"` with reason "{Client} can't install this plugin, and it has no skills
     to copy." or "{Client} can't install this plugin, and its skills need the rest of it."
- `warn` on a plugin "+ Add" when this client already has a plugin with the same name from
  another marketplace: "{Client} already has {name} from {marketplace}. It will load both."
- For skills: installed word → state `"on"`, where = word lowercased ("via plugin");
  route → `add` "+ Add" (`skill.install`); not self-contained and its plugin has a route here →
  `add` "Add the plugin" (`plugin.install`, `plugin` = the skill's plugin); else `"none"`, reason
  "This skill needs its plugin, and {Client} can't install that plugin."
- A row is left out when no visible (not hidden) column has a state other than "none" or an
  `add`. `same_name`: another row of the same kind (before filters) has the same name.
- Order: mine first; with `q`, search rank inside each group; else name, then source.
- Note text: `"{Client} gets the {marketplace} marketplace the first time you add one of its
  plugins."`, once per (client, marketplace).
- `GET /api/library?project=&kind=&show=&q=&category=&hidden=cursor,codex&attention=1` →
  `{"project": ..., **library(...)}`; unknown kind → `"mcp_server"`, unknown show → `"mine"`.
- `GET /api/offer?kind=plugin|skill&id=` → the catalog or skill catalog dict; 404
  "Not on this computer." when unknown.
