# Kitden 0.13.0 — new: Claude account plugins in the Library; Codex skills in sub-folders

Kitden 0.13.0 lists the plugins your Claude account gives Claude Code in their own Library group, and you can turn them off from there. It also finds Codex skills in sub-folders, and Context says how your skill list stands now, not only how it stood in your last chat. Kitden follows `CLAUDE_CONFIG_DIR`, and many states the page shows are now closer to what the clients really do.

## New

- **The plugins of your Claude account are in the Library.** A group called **From your Claude account** lists the plugins the Claude app gives Claude Code, each with what it holds. **Turn off for all projects…** and **Turn off in this project…** work as for any plugin, with a preview, a backup and Undo, and the plugin stays in your account. On Context, their skills name their plugin and offer its switch. ([#219](https://github.com/KonstantinStarovoytov/kitden/pull/219)) @KonstantinStarovoytov
- **Kitden finds Codex skills in sub-folders.** A skill inside a skills folder's sub-folder, also one inside another skill's folder, now has a row in the Library and a switch on Context. Removing a skill whose folder holds other skills says so in the review, and a skill linked from one Codex folder to the other is one row, not two. ([#217](https://github.com/KonstantinStarovoytov/kitden/pull/217)) @KonstantinStarovoytov

## Better

- **Context says how your skill list stands now.** When skills were added, turned off or turned on after your last chat, or the limit changed, an estimate under the chat's sentence says how many skills or descriptions would be cut now. The bar and the boxes show it too, for Claude Code and for Codex. A Codex skill that is off no longer counts in any estimate. ([#215](https://github.com/KonstantinStarovoytov/kitden/pull/215), [#216](https://github.com/KonstantinStarovoytov/kitden/pull/216)) @KonstantinStarovoytov
- **The limit line counts the changes waiting in the preview.** With skills set to Off and not yet applied, the line and the verdict now count the same skills. ([#215](https://github.com/KonstantinStarovoytov/kitden/pull/215)) @KonstantinStarovoytov
- **A stack on the map shows which of its cards the selected client loads.** The client's cards come to the front of the stack, the others dim, and the badge reads "3 of 55" instead of "+52". Before, every front card looked loaded. ([#220](https://github.com/KonstantinStarovoytov/kitden/pull/220)) @KonstantinStarovoytov
- **Kitden follows `CLAUDE_CONFIG_DIR`.** With it set, or `CLAUDE_CODE_PLUGIN_CACHE_DIR`, Kitden reads and writes Claude Code's files in that folder, not in `~/.claude`. Before, it showed none of your settings, plugins and chats. The page also notices a client folder that is made after it started. ([#213](https://github.com/KonstantinStarovoytov/kitden/pull/213)) @KonstantinStarovoytov
- **The Instructions map matches Codex and Cursor.** Codex shows no `AGENTS.md` in a project marked untrusted, and Cursor shows a `CLAUDE.md` at a project's root. ([#203](https://github.com/KonstantinStarovoytov/kitden/pull/203)) @KonstantinStarovoytov

## Fixed

- **Claude Code items show the state they really have.** A hook whose `if` never matches shows as Off. A plugin that only a project turns on and that is not installed shows as Unknown, not On. A server you turned off with `/mcp` in one project shows as Off there. A hook on the new `PreSkillShellCommand` event with `if` shows as On. ([#201](https://github.com/KonstantinStarovoytov/kitden/pull/201), [#211](https://github.com/KonstantinStarovoytov/kitden/pull/211)) @KonstantinStarovoytov
- **A skill's `when_to_use` counts in the Claude Code skill list.** Kitden counted only the description, so sizes were too small and the estimate could be missing. ([#202](https://github.com/KonstantinStarovoytov/kitden/pull/202)) @KonstantinStarovoytov
- **A quoted skill description is counted as the client reads it.** A description in quotes with `\"` inside no longer shows backslashes in Details, and its length on Context matches what the client sends. ([#214](https://github.com/KonstantinStarovoytov/kitden/pull/214)) @KonstantinStarovoytov
- **The Add panels have an even gap above the hint.** The closed "Add a GitHub source" block no longer takes a row of its own. ([#204](https://github.com/KonstantinStarovoytov/kitden/pull/204)) @KonstantinStarovoytov
- **Copies of a skill, worktree plugins and removed skills show the right state.** Two Codex skills of one name are off only when every copy is off. A project plugin installed in the main checkout shows as On in a git worktree made with `--relative-paths`. Removing a skill that holds other skills names the inner skills that are off, and a quoted description over several lines is read whole. ([#218](https://github.com/KonstantinStarovoytov/kitden/pull/218)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`. The gateway did not change, so your agents need no restart. Requires macOS or Linux.

Nothing new goes online. What Kitden reads and writes changes a little:

- Kitden reads the Claude app's own folder for the plugins your account gives Claude Code: its list, each plugin's `plugin.json` and the names of what it holds. Turning one off writes `"<name>@inline": false` in `enabledPlugins` of Claude Code's settings, in your settings or the project's local settings, with a backup and Undo. Nothing goes to your account.
- With `CLAUDE_CONFIG_DIR` or `CLAUDE_CODE_PLUGIN_CACHE_DIR` set, Kitden reads and writes in those folders.
- Kitden reads skill files deeper in Codex's skills folders, and a skill's `when_to_use` for its size. It keeps none of it.
- In a project that is a git worktree, Kitden reads the `.git` file in its folder, which names the main checkout. It runs no git command.

See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.13.0/PRIVACY.md).

Limits:

- The account plugins were read from the Claude app 6.28899.6 on macOS. The Linux app was not checked, and neither was what the app does with a plugin turned off in your account. The terminal's own copies of these plugins are not read, so after a terminal chat Context does not count their skills for the next chat.
- A variable set in the `env` of a settings file is not followed. Cursor's use of `CLAUDE_CONFIG_DIR` was not checked.
- Codex's limits on how deep it looks, and its linked folders, were read from its source and not seen on a real list. Copying an outer Codex skill brings its inner skills, and the review does not name them.
- The estimate on Context follows the rule and was not checked against a real chat after a change. A Codex plugin added after the last chat is not counted.
- A hook on `PreSkillShellCommand` shows as On also in Claude Code before 2.1.332, which ignores that event.
- Before/after pictures of the new Library group and the stacks are not in the README.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.13.0/docs/development.md#check-before-a-release) have not all been completed.
