# Kitden 0.9.0 — map stacks and a truer Context page

Kitden 0.9.0 folds big groups on the Gateway and Library maps into stacks of cards, so a large setup is easy to scan, and both pages now open on the map at any size. The Context page shows your newest chat, marks large skills in orange and says how much of a cut description was sent. `kitden open` also restarts a page left over from an older version.

## New

- **Card stacks on the Gateway and Library maps.** A group of two or more starts folded as a small stack of cards, and the tops show the first names. Press a stack to open it: a big group shows five cards at a time, and **Collapse** folds it back. Both pages now open on the map at any size, not on the List past 15 items. A change waiting in the tray never hides in a stack. ([#77](https://github.com/KonstantinStarovoytov/kitden/pull/77)) @KonstantinStarovoytov
- **Context shows how much of a cut description was sent.** On the "Cut short" side, a pill such as "342 of 570" says how many characters of the description the chat sent. ([#78](https://github.com/KonstantinStarovoytov/kitden/pull/78)) @KonstantinStarovoytov

## Better

- **Large skills stand out on Context.** On the side whose descriptions are sent, each skill and its piece of the skill list bar go from grey to orange with the length of its description. The skill whose Details are open gets a dark ring instead. ([#72](https://github.com/KonstantinStarovoytov/kitden/pull/72)) @KonstantinStarovoytov
- **Context follows your newest chat and the client's own rules.** Kitden takes the skill list sent last, not the chat file changed last. For Codex, it follows Codex's own cut rule and uses `model_context_window` from `config.toml`. For Claude Code, it reads the skills the Claude app adds, so it can check its estimate against your chat. ([#73](https://github.com/KonstantinStarovoytov/kitden/pull/73)) @KonstantinStarovoytov
- **A skill from a plugin updated after the chat is still counted.** Codex removes the old plugin folder on update, so Kitden reads the same skill from the newest version folder instead of setting it aside. The pill says so. If the new description changes the result, the check fails and Kitden shows no estimate. ([#78](https://github.com/KonstantinStarovoytov/kitden/pull/78)) @KonstantinStarovoytov
- **The plugin comes from released builds only.** Both plugin marketplaces now read the plugin from a `release` branch, so you get the plugin only after a release. ([#71](https://github.com/KonstantinStarovoytov/kitden/pull/71)) @KonstantinStarovoytov

## Fixed

- **`kitden open` after an upgrade in a terminal.** The page that was already running kept going without its files, so `kitden open` gave a link that answered with an error. Now the page records its version, and `kitden open` stops a page of another version (or an old one with no version) and starts a new one. If the old page does not stop, it says so. ([#70](https://github.com/KonstantinStarovoytov/kitden/pull/70)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`, or with the Update button on the page. An update from the page needs no restart. After an update in a terminal, run `kitden open` to get the new page. If a gateway cannot move to the new version by itself, it keeps working on the old one until the agent restarts. Requires macOS or Linux.

Nothing new goes online. Context reads more of the client's own files on your computer: Codex's `config.toml` and model list, and the Claude app's skill folder. It keeps none of it. See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.9.0/PRIVACY.md).

Known limits of the Context check: the model window table and the 15 built-in skills stay as hints, and every chat checks them. If they are wrong, Kitden shows no estimate rather than wrong numbers. One real Codex list and two real Claude Code chats were checked; other versions and Linux were not. With both a uv and a Homebrew copy installed, `kitden open` from the other copy restarts the page.

Kitden is still alpha: the real-client checks in
[Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.9.0/docs/development.md#check-before-a-release)
have not all been completed.
