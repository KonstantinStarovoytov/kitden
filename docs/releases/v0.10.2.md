# Kitden 0.10.2 — a scan that says what to do next

Kitden 0.10.2 makes `kitden scan` more useful. It names the skills that did not fit, shows your last chat even when you run it in a folder with no chat, and ends with the next step. Secrets in a server's command arguments now go to the Keychain or keyring when the server moves into the gateway. The README now shows the scan command on its first screen.

## Better

- **`kitden scan` names the skills that did not fit.** Under the Skill list line it lists the first five skills your last chat sent by name only (Claude Code) or cut (Codex), then `+N more`. It prints the warnings in words with the number of notes and `kitden show findings`, and ends with `To fix: kitden open`. `kitden scan --json` does not change. `kitden show context` also gives the names to your agent. See "Upgrade and limits". ([#156](https://github.com/KonstantinStarovoytov/kitden/pull/156)) @KonstantinStarovoytov
- **`kitden scan` shows your last chat when the folder has none.** A new terminal opens in your home folder, where nobody chats, so the scan said "No Claude Code chat yet". Now it reads the client's last chat in any folder and says which folder that was. A chat whose folder changed while it ran now counts in each folder it was in, so an older chat no longer takes its place. The page and `kitden show context` still answer for the project you ask about. ([#158](https://github.com/KonstantinStarovoytov/kitden/pull/158)) @KonstantinStarovoytov
- **`kitden scan` says when it waits for Codex, and does not wait twice.** While Codex lists its plugins (up to 15 seconds), the terminal says so on stderr, so `--json` output stays valid. Kitden keeps the answer for one hour while Codex's `config.toml` is unchanged. See "Upgrade and limits". ([#155](https://github.com/KonstantinStarovoytov/kitden/pull/155)) @KonstantinStarovoytov

## Fixed

- **Secrets in a server's arguments no longer stay in `gateway.json`.** When a server moved into the gateway, a value like `--token=…`, `NAME_API_KEY=…` or the one after `--password` was copied as plain text. Now the secret part goes to the macOS Keychain or the Linux keyring, as secrets in `env` and headers already did, and the flag stays readable. A server moved in by an earlier Kitden shows **Move secrets to the Keychain…** in its Details, with preview, Apply and Undo. ([#157](https://github.com/KonstantinStarovoytov/kitden/pull/157)) @KonstantinStarovoytov

## Documentation

- **The README shows how to try Kitden on its first screen.** The command `uvx --python 3.13 kitden scan` sits under the tagline, with a line saying the scan only reads. The desk button and the contributor links moved to a "Help build Kitden" part near the end. ([#154](https://github.com/KonstantinStarovoytov/kitden/pull/154)) @KonstantinStarovoytov
- **Help for a first contribution.** The README links to open good first issues, and the contributing guide explains how to claim a code change, send a test report, add a pull request number to the roadmap and ask for help with a fork. ([#142](https://github.com/KonstantinStarovoytov/kitden/pull/142)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`, then restart your agents once so they start the gateway of the new version, which puts secret arguments back when it starts a server. Requires macOS or Linux.

Nothing new goes online. What changes is what Kitden stores and prints:

- Kitden keeps Codex's plugin answer in `codex-plugins.json` in its own data folder. It holds only each plugin's id and whether it is on, and only its owner can read it. It is used for one hour, while `config.toml` is unchanged. Kitden writes it only when Codex answered.
- `kitden scan` prints in your terminal the names of the skills that did not fit and, when it used a chat from another folder, that folder's path. `kitden show context` prints the skill names into your chat, so your agent and the company behind it see them. They are names, not secret values. See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.10.2/PRIVACY.md).
- Secrets in a moved server's arguments are now stored in the Keychain or keyring, not in `gateway.json`.

Limits:

- The Keychain change was tested with a stand-in Keychain. The nightly check with the real Keychain was not run for this pull request.
- The stored Codex answer was not checked with a real Codex run that has remote plugins.
- The printed lines `kitden open` and `kitden show findings` need `uvx --python 3.13` in front when you ran the scan with `uvx` and have no `kitden` command yet.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.10.2/docs/development.md#check-before-a-release) have not all been completed.
