# Kitden 0.11.0 — choose which clients Kitden reads

Kitden 0.11.0 lets you turn a client off. If you use only Claude Code, you can switch off Codex and Cursor, and Kitden stops reading them. `kitden scan` now puts the skills that did not fit first and counts in plain words. Picking a project is quicker, a plugin update no longer makes a skill look cut, and the pages say more clearly what they show.

## New

- **Choose which clients Kitden reads.** **Choose clients…**, a button at the top right of the Overview, the Library, the Gateway and the Context page, opens a panel with a switch for Claude Code, Codex and Cursor. A switch acts at once, with an Undo in the toast. A client that is off is not read, shown or offered anything: not on the page, not in `kitden scan`, not in `kitden show`, not in the agent tools. With Codex off, the wait for `codex plugin list` is gone. Nothing in the client's own files changes, and the gateway is not touched: a client that is off keeps its `kitden` entry. One client always stays on. An Undo of an earlier change to a client that is off waits until you turn it on. Each page says which clients are off, such as "Cursor is turned off in Kitden." See "Upgrade and limits". ([#171](https://github.com/KonstantinStarovoytov/kitden/pull/171), [#172](https://github.com/KonstantinStarovoytov/kitden/pull/172)) @KonstantinStarovoytov

## Better

- **`kitden scan` puts what did not fit first and counts in plain words.** Each client is a block. It starts with the verdict on your last chat, such as "3 of 19 skills showed only a name", with their names. One line, "On this computer: 2 plugins, 4 skills, 2 MCP servers", replaces the count lines, and a line says why a chat's skill count differs. Kinds read as `MCP servers`, `Hooks` and `Plugins`, not internal names. A client with no skills says "nothing yet", and one that is not installed says `Codex: not found`. The Claude Desktop Code tab is one line under Claude Code. A line no longer breaks inside `kitden show findings` or "+26 more". A skill reached twice counts once. A file Kitden cannot read gets a reason in words. The notes say "(nothing to fix)", and the last line says what to do. `kitden scan --json` and the exit codes do not change. ([#168](https://github.com/KonstantinStarovoytov/kitden/pull/168), [#178](https://github.com/KonstantinStarovoytov/kitden/pull/178)) @KonstantinStarovoytov
- **Picking a project is quicker.** When a project's last Claude Code chat is far down the list of chats, Kitden no longer reads every newer chat log in full. On one real setup the read of the logs went from about 4 seconds to about 1 second. The answer is the same. ([#172](https://github.com/KonstantinStarovoytov/kitden/pull/172)) @KonstantinStarovoytov
- **The Overview opens fast with many projects.** To count the projects with rules of their own, it built the whole Library map for each one: 12 seconds for 26 projects on a real setup. It now checks only the rules, and draws as soon as its own read arrives. ([d45ccfd](https://github.com/KonstantinStarovoytov/kitden/commit/d45ccfd)) Amanda Woodward
- **The pages say more plainly what they show.** The Overview has a plain title and a lede that names your clients, and notes with the same words fold into one row. The Library and Gateway ledes say what the page is. The Library's client blocks say what each client loads, not "Connected", and are wide enough for it. A skill pill on the Context page says what its number is, and a plugin skill shows its plugin. A search on the Library or Gateway map scrolls to its first match. A change of several rows reads in the past tense. The Instructions tab says an empty map once. ## Fixed

- **A description that a plugin update changed is no longer counted as cut.** When Codex updated a plugin after your last chat and a skill's description changed with it, Kitden compared what the chat sent with the new text and said it was cut. One real scan said "31 of 61 cut" for 30 real cuts. Now Kitden leaves that skill out of the count and says it cannot tell for it. The check against Codex's rule passes again when the other skills match. ([#166](https://github.com/KonstantinStarovoytov/kitden/pull/166)) @KonstantinStarovoytov
- **A client's block on the Library map agrees with what is under it.** On the Instructions tab it counted commands and agents as files, so a block could say "2 files" above "Claude Code loads no instruction file". It now counts instruction files, and says "Commands and agents only" when those are all a client reads. On the Plugins and skills tab, a client whose only item is a hook said "Nothing loaded". It now says "1 hook". ([ea775af](https://github.com/KonstantinStarovoytov/kitden/commit/ea775af)) Amanda Woodward
- **The hint strip no longer shows page text through it.** The strip is solid under its words. ([3a8db63](https://github.com/KonstantinStarovoytov/kitden/commit/3a8db63)) Amanda Woodward

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`. The gateway did not change, so your agents need no restart. Requires macOS or Linux.

Nothing new goes online. What changes is what Kitden stores and reads:

- Which clients you turned off is kept in `clients.json` in Kitden's own data folder, such as `{"off": ["codex"]}`. A missing or broken file means none is off. It is Kitden's own choice, not a client's settings.
- A client that is off is not read, and none of its commands are run.
- To pick a project faster, Kitden searches a Claude Code chat log for the time of its newest skill list before it reads the log in full. It reads the same files as before and keeps none of it.

See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.11.0/PRIVACY.md).

Limits:

- A client that is off keeps working with the Kitden gateway. Turning it off in Kitden does not disconnect it.
- A note that Cursor loads a skill from Claude Code's folder still names Claude Code when Claude Code is off.
- Choosing clients was tried on sandbox homes, the demo and one real setup. A narrow window and reduced motion were not checked.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.11.0/docs/development.md#check-before-a-release) have not all been completed.
