# Kitden 0.11.0 — choose which clients Kitden reads

Kitden 0.11.0 lets you turn off the clients you do not use. A button, **Choose clients…**, sits at the top right of the Overview, the Library, the Gateway and the Context page. A client you turn off is not read, shown or offered anywhere. This release also makes `kitden scan` print its counts in plain words, opens the Overview faster when you have many projects, fixes a wrong "cut" count for Codex skills after a plugin update, and polishes the wording of the pages.

## New

- **Choose which clients Kitden reads.** **Choose clients…** opens a panel with a switch for Claude Code, Codex and Cursor. A client that is off is not scanned and no command of it runs, so the 15-second wait for Codex's plugin list is gone. It leaves the pages, `kitden scan` (`Codex: turned off in Kitden`), `kitden show` and the agent tools. Nothing in the client's own files changes, and a client that uses the Kitden gateway keeps working. A switch acts at once, with a toast and Undo. One client always stays on. An Undo of an earlier change to an off client waits with "Turn Codex on to undo this." See "Upgrade and limits". ([#171](https://github.com/KonstantinStarovoytov/kitden/pull/171)) @KonstantinStarovoytov

## Better

- **`kitden scan` prints its counts in plain words.** `mcp_server: 12` now reads `MCP servers: 12`, and the other kinds read the same way. The `Skills` line says why its number differs from the last chat's. The Claude Desktop Code tab is one line under Claude Code. A client that is not installed reads `Codex: not found`. `kitden show findings` and "+26 more" no longer break across two lines, and a skill reached twice, by a project's path and by a link to it, counts once. `scan --json` does not change. ([#168](https://github.com/KonstantinStarovoytov/kitden/pull/168)) @KonstantinStarovoytov
- **Picking a project is quicker.** Kitden no longer reads in full every newer Claude Code chat log to find a project's last skill list. On one real setup the read of the logs went from 3.9 to 1.0 seconds. The answer is the same. ([#172](https://github.com/KonstantinStarovoytov/kitden/pull/172)) @KonstantinStarovoytov
- **The Overview opens fast with many projects.** To count the projects with rules of their own it built the whole Library map for each one. It now checks only the rules, and draws as soon as its own read arrives. ([d45ccfd](https://github.com/KonstantinStarovoytov/kitden/commit/d45ccfd)) Amanda Woodward
- **Choose clients… is easy to find, and each page says which clients are off.** The button is a plain button at the top right of the four pages. A quiet line such as "Cursor is turned off in Kitden." names each client that is off. The empty Instructions map says "No instruction files here." only when no note already says why. ([#172](https://github.com/KonstantinStarovoytov/kitden/pull/172)) @KonstantinStarovoytov
- **Plainer pages.** The Overview is titled "Overview", with a lede that names your clients, and notes with the same words fold into one row, such as "46 items load from another client." The Library and Gateway ledes say what each page is. A change of several rows reads in the past tense. The hint line is solid under its words and no longer lies over page text. ([f59e749](https://github.com/KonstantinStarovoytov/kitden/commit/f59e749), [6d660a3](https://github.com/KonstantinStarovoytov/kitden/commit/6d660a3), [d456100](https://github.com/KonstantinStarovoytov/kitden/commit/d456100), [3a8db63](https://github.com/KonstantinStarovoytov/kitden/commit/3a8db63)) Amanda Woodward
- **The maps and the Context page say more.** A search on the Library or Gateway map scrolls to its first match. On the Context page, a skill pill says what its number is and shows a plugin skill's plugin. A client block on the Library map says what that client loads, not "Connected", and is wide enough for it. ## Fixed

- **A description that a plugin update changed is no longer counted as cut.** When Codex updated a plugin after your last chat and a skill's description changed with it, Kitden compared what the chat sent with the new text and called it cut. One real scan said "31 of 61 descriptions were cut" when 30 were. Now Kitden leaves that skill out of the count and says it cannot tell, and the check against Codex's rule passes again. ([#166](https://github.com/KonstantinStarovoytov/kitden/pull/166)) @KonstantinStarovoytov
- **A client block on the Library map agrees with what is under it.** On the Instructions tab it counted commands and agents as files, so it could say "2 files" above "Claude Code loads no instruction file". It now counts instruction files, and says "Commands and agents only" when that is all a client reads. On the Plugins and skills tab, a client whose only item is a hook said "Nothing loaded"; it now says "1 hook". ([ea775af](https://github.com/KonstantinStarovoytov/kitden/commit/ea775af)) Amanda Woodward

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`, then restart your agents once so they start the gateway of the new version. Requires macOS or Linux.

Nothing new goes online. What Kitden stores changes in one way: your choice of clients is kept in `clients.json` in Kitden's own data folder, for example `{"off": ["codex"]}`. It changes nothing in any client's files. A missing or broken file means no client is off. A client that is off is not read, and none of its commands run. See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.11.0/PRIVACY.md).

Limits:

- Turning a client off does not disconnect it from the Kitden gateway. Its `kitden` entry stays and keeps working.
- A preview made before a client was turned off is not applied until you turn that client on.
- The README pictures of the pages show the old page heads until they are recorded again.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.11.0/docs/development.md#check-before-a-release) have not all been completed.
