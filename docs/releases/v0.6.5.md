# Kitden 0.6.5 — more servers fit the gateway, clearer words

Kitden 0.6.5 is a small release. A server that starts in its own folder can now move into the
Kitden gateway, the page says when an app writes a server back, and the tools of `kitden mcp`
say when to use each one. One fix came from an outside contributor.

## New

- **A server that starts in its own folder can move into the gateway.** The gateway starts it in that folder, so it works in every client, also in Cursor, which has no start folder setting. A folder the client fills in, or one that is not on this computer, still stays direct, with the reason. ([82d25dd](https://github.com/KonstantinStarovoytov/kitden/commit/82d25dd)) @KonstantinStarovoytov
- **Servers that apps write back.** When a server runs from a Mac app such as Pen, the review says the app may write it back, the Gateway names the app when its entries differ, and Changes and Overview say when a removed server is back. Its Overview card opens the entries outside the gateway. ([273cf16](https://github.com/KonstantinStarovoytov/kitden/commit/273cf16)) @KonstantinStarovoytov, ([14a68a4](https://github.com/KonstantinStarovoytov/kitden/commit/14a68a4)) @KonstantinStarovoytov

## Better

- **The MCP tools say when to use each one.** Every tool description of `kitden mcp` names the tool to use instead, and `project_path` explains what it takes. ([7e2c0a8](https://github.com/KonstantinStarovoytov/kitden/commit/7e2c0a8)) @KonstantinStarovoytov
- **Clearer reasons a server stays outside the gateway.** "needs values its client fills in when it starts" instead of "reads values from your shell", and "must start in its own folder" with the folder's name. ([18ecdfa](https://github.com/KonstantinStarovoytov/kitden/commit/18ecdfa)) @KonstantinStarovoytov
- **A fast Apply no longer flickers.** When the write ends within 300 ms, the bar keeps its words and goes straight to Applied. ([b395c11](https://github.com/KonstantinStarovoytov/kitden/commit/b395c11)) @KonstantinStarovoytov

## Fixed

- **The toast names the client that refused a change.** When a client's own command fails, "Nothing was changed" says "Claude Code refused the change" instead of "The change did not check out". ([7838462](https://github.com/KonstantinStarovoytov/kitden/commit/7838462)) @chiragjangiir
- **Remove works for plugins when Claude Code was started in the home folder.** Kitden no longer reads `~/.claude/settings.json` a second time as a project's file, so Remove no longer runs a project uninstall that Claude Code refuses. ([7fe3046](https://github.com/KonstantinStarovoytov/kitden/commit/7fe3046)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`, then start a new session in
your clients so they start the new gateway. Requires macOS or Linux. Kitden is still alpha: the
real-client checks in
[Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.6.5/docs/development.md#check-before-a-release)
have not all been completed.
