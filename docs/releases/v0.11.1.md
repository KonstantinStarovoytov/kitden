# Kitden 0.11.1 — fix: the right chat is "your last chat"; Kitden uses your skill list limit

Kitden 0.11.1 names the right chat as your last chat, and `kitden show context` finds it from any folder. When you set Claude Code's own limit for the skill list, Kitden now uses it. The release's own title now comes from its notes.

## Better

- **Kitden uses the skill list limit you set in Claude Code.** Claude Code lets you change how much of the context window the skill list may use (`skillListingBudgetFraction`, 1% by default) and the length of one description (`skillListingMaxDescChars`, 1536 by default). Kitden read neither, so the limit on the Context page and the estimates for another window or after Apply were wrong for you. Kitden now reads both from Claude Code's settings (yours, the project's and the local one). When a number comes from one of them, the Context page says so, such as "The limit is skillListingBudgetFraction in Claude Code's settings: 2% of the context window." When `SLASH_COMMAND_TOOL_CHAR_BUDGET` is set too, it wins, as before. This order is a guess, because Claude Code's docs do not say which wins. The verdict on your last chat did not change: it is read from the chat's log. See "Upgrade and limits". ([#185](https://github.com/KonstantinStarovoytov/kitden/pull/185)) @KonstantinStarovoytov

## Fixed

- **"Your last chat" is the chat you were last in.** A later list of added skills also made a chat "the last chat", and the Claude app can add skills to a chat nobody is in. On one real setup two old chats became "your last chat", and the scan and the Context page said "3 of 90 skills showed only a name" while every chat of that week had 22. Now it is the chat with the newest full skill list, which Claude Code sends when a chat starts or is resumed. A chat's own verdict still counts the skills added to it. ([#182](https://github.com/KonstantinStarovoytov/kitden/pull/182)) @KonstantinStarovoytov
- **`kitden show context` finds your last chat from any folder.** In a folder with no chat, such as your home folder, it said "No Claude Code chat yet" while `kitden scan` found the chat. It now takes the last chat in any folder and names that folder, as the scan does. With `--project` it stays with that folder. See "Upgrade and limits". ([#182](https://github.com/KonstantinStarovoytov/kitden/pull/182)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`. The gateway did not change, so your agents need no restart. Requires macOS or Linux.

Nothing new goes online. What Kitden reads and prints changes a little:

- Kitden reads `skillListingBudgetFraction` and `skillListingMaxDescChars` from Claude Code's settings files, which it already read. It keeps nothing of them.
- With no chat in the folder, `kitden show context` reads your last chat in any folder, as `kitden scan` does, and prints that folder's path. The plugin's `context` skill runs this command, so your agent and the company behind it see the path in the chat.

See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.11.1/PRIVACY.md).

Limits:

- Kitden has not been tried against a real Claude Code with `skillListingBudgetFraction` set. The order against `SLASH_COMMAND_TOOL_CHAR_BUDGET`, and what Claude Code does with a value that is not allowed, are not confirmed. Kitden ignores such a value.
- Codex's last chat is found as before. It was not checked for the first case above.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.11.1/docs/development.md#check-before-a-release) have not all been completed.
