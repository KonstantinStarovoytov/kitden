# Kitden 0.10.3 — clearer access in the gateway

Kitden 0.10.3 makes a gateway server's access easier to read and to add. Details shows Add access… once, offers Sign in only when the server has it, and the map shows **Needs key** when a catalog says a server needs a key. Hooks that Claude Code's `disableAllHooks` turns off now show as off, and built-in skills are marked on the Context page. The README names Homebrew next to the scan command.

## Better

- **Add access… is clearer in a gateway server's Details.** It shows once, not twice. Kitden asks the server first, so **Sign in** shows only when the server has a browser sign-in, and a server that needs nothing says so. Sign in runs inside the same form, Token and Header stay one click away, and every access form has **Back** to Details. The buttons say what they add (**Add token**, **Add header**, **Add variable**). Details show what the server does: the catalog's description, else the server's own words. See "Upgrade and limits". ([#163](https://github.com/KonstantinStarovoytov/kitden/pull/163)) @KonstantinStarovoytov
- **The map shows Needs key when a catalog says a server needs one.** The warning names the key, for example `X-Cohere-Api-Key`, and Add access… comes with that name filled in and the catalog's words on where to get it. Kitden learns this when you add a server from a catalog, find it there again, or press **Rescan**. **Rescan** now asks the Official MCP Registry about each gateway server by its name. See "Upgrade and limits". ([#163](https://github.com/KonstantinStarovoytov/kitden/pull/163)) @KonstantinStarovoytov
- **The Gateway page opens at once after a reload.** It no longer waits for the Overview's read of the chat logs (6.6 seconds on a large setup) and shows its skeleton all that time. A change the stopped page could not prepare now says "Kitden is not running". ([#163](https://github.com/KonstantinStarovoytov/kitden/pull/163)) @KonstantinStarovoytov
- **Built-in skills are marked on the Context page.** Skills built into Claude Code, such as `dataviz`, are not files on your computer, so the Library cannot show them and Kitden cannot turn them off. Their pills now say **built-in**, with a tooltip, and their Details say the same. ([#164](https://github.com/KonstantinStarovoytov/kitden/pull/164)) @KonstantinStarovoytov

## Fixed

- **Hooks turned off by `disableAllHooks` show as off.** When Claude Code's `disableAllHooks` is true, Claude Code runs no hooks from its settings files, but Kitden showed them as on. Now they show as off on the maps and in Details, with the settings file that decides. Kitden reads the flag as Claude Code does: local settings over the project's shared settings over yours, so a project can turn your hooks back on in that project only. Managed settings, `--settings` on the command line, and hooks from plugins are not covered. ([#162](https://github.com/KonstantinStarovoytov/kitden/pull/162)) @KonstantinStarovoytov
- **A stale "Needs token" clears.** One refused call kept the warning for good. It now clears once the server answers again. ([#163](https://github.com/KonstantinStarovoytov/kitden/pull/163)) @KonstantinStarovoytov

## Documentation

- **The README names Homebrew next to the scan command.** People with Homebrew and no uv see `brew install konstantinstarovoytov/tap/kitden`, then `kitden scan`, on the first screen. ([#159](https://github.com/KonstantinStarovoytov/kitden/pull/159)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`, then restart your agents once so they start the gateway of the new version. Requires macOS or Linux.

What goes online and what Kitden stores changes in the gateway:

- **Rescan** asks the Official MCP Registry about each server in the Kitden gateway: one search per server, which carries the server's name. As with any web request, the registry sees your IP address. Kitden keeps what the registry says of the server (its description and the keys it requires) in `gateway-catalog.json` in its own data folder. Automatic rescans do not ask.
- Kitden keeps what each gateway server says it does, in its own words, in `gateway-about.json` in the same folder.
- Add access… now asks the remote server you added, with no value, what access it takes. This is the same kind of request as the calls Kitden already makes to the servers you add.

See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.10.3/PRIVACY.md).

Limits:

- `disableAllHooks` is read from the settings files only.
- Built-in skills cannot be turned off from Kitden.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.10.3/docs/development.md#check-before-a-release) have not all been completed.
