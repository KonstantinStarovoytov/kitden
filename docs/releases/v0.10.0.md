# Kitden 0.10.0 — one gateway, truer approvals

Kitden 0.10.0 shows the real state of two things it had wrong: whether Claude Code approved a project's servers, and which Codex plugins a project turns on or off. Kitden now works with its own gateway only: Obot and MetaMCP are gone. Secrets in the macOS Keychain come back as they went in, and the plugin installs in Claude Code without a GitHub SSH key. Thanks to @Mr45401 for Cursor skills in sub-folders.

## New

- **Codex plugins turned on or off in one project.** A trusted project's `.codex/config.toml` can switch an installed plugin on or off there. Kitden shows that choice as a project row, counts it in what the project loads, and turns it on or off with preview, backup and Undo. It offers no Remove, because removing uninstalls the plugin everywhere. ([#115](https://github.com/KonstantinStarovoytov/kitden/pull/115)) @KonstantinStarovoytov

## Better

- **Kitden works with its own gateway only.** Obot, MetaMCP and a gateway added by its address are gone. The Gateway page has no "Add another gateway…", no "Use this gateway…" and no moving servers into an outside gateway. Only the Kitden gateway (`kitden mcp`) stays. See "Upgrade and limits". ([#116](https://github.com/KonstantinStarovoytov/kitden/pull/116)) @KonstantinStarovoytov
- **A tool that is off says so in Kitden's words.** With strict mode on, or a rule that turns a tool off for a project, a call gets "<name> is turned off in Kitden." instead of "Unknown tool". A tool turned on during a session can now be called, even if it was not offered when the session started. ([#121](https://github.com/KonstantinStarovoytov/kitden/pull/121)) @KonstantinStarovoytov
- **A secret too long for the macOS Keychain is refused before anything changes.** Before, it was stored cut. The preview now says how long it is, how long Kitden can store, and what to do: keep the server in the client's own settings, or use a shorter token. A sign-in too long to save no longer replaces the one saved before. ([#114](https://github.com/KonstantinStarovoytov/kitden/pull/114), [#121](https://github.com/KonstantinStarovoytov/kitden/pull/121)) @KonstantinStarovoytov
- **Cursor skills in sub-folders show up.** Cursor lets you sort skills into category folders under `.cursor/skills` and the other skill folders it reads. Kitden now finds them up to four levels down, keeps each skill's own name, and removing one deletes only that skill's folder. ([#104](https://github.com/KonstantinStarovoytov/kitden/pull/104)) @Mr45401
- **Catalogs can show Kitden's icon.** The MCP Registry entry now names the house icon, so catalogs that read the registry can show it instead of letters. It reaches the registry with this release. ([#128](https://github.com/KonstantinStarovoytov/kitden/pull/128)) @KonstantinStarovoytov

## Fixed

- **Claude Code project servers show as approved or rejected again.** Claude Code keeps these approvals in its settings files, and moves older ones out of `~/.claude.json`. Kitden read only `~/.claude.json`, so every project server showed as unknown. It now reads the user, project and local settings files and follows folder trust as Claude Code does. ([#115](https://github.com/KonstantinStarovoytov/kitden/pull/115)) @KonstantinStarovoytov
- **The Claude Code plugin installs without a GitHub SSH key.** `claude plugin install kitden@kitden` failed with "Host key verification failed" on a machine with no GitHub SSH set-up. The marketplace file now names the https address. The fix reaches you without a release, because clients read the marketplace file from `main`. ([#106](https://github.com/KonstantinStarovoytov/kitden/pull/106)) @KonstantinStarovoytov
- **Secrets with letters outside ASCII work in the macOS Keychain.** A value such as `日本` was written, then read back as hex, and Kitden said it could not reach the Keychain. It is now stored and read back whole. ([#114](https://github.com/KonstantinStarovoytov/kitden/pull/114)) @KonstantinStarovoytov
- **Two odd secrets get a true error.** A value with a lone surrogate raised an error nobody caught, and a value in the Linux keyring that is not UTF-8 was reported as "could not reach the keyring". Both now say Kitden could not read or store the secret. ([#121](https://github.com/KonstantinStarovoytov/kitden/pull/121)) @KonstantinStarovoytov

## Documentation

- **The README follows GitHub's theme at once, and shows the mcprush badge.** Switching GitHub's theme on an open README page used to leave the pictures dark until a reload. The PyPI page looks as before. ([#126](https://github.com/KonstantinStarovoytov/kitden/pull/126), [#127](https://github.com/KonstantinStarovoytov/kitden/pull/127)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`, then restart your agents once so they start the new gateway. Requires macOS or Linux.

**Outside gateways are gone.** If you used Obot, MetaMCP or a gateway added by its address:

- Kitden deletes its saved list of outside gateways (`settings.json` in Kitden's data folder, which held nothing else) when it starts.
- A client entry that pointed at an outside gateway is left as it is. It shows as an ordinary remote server, and you can remove it or move it into the Kitden gateway.
- Old changes that wrote into an outside gateway leave the Changes page. Their files and backups stay on disk.
- "Log in:" notes are gone, because only connecting a client to an outside gateway made them.

Kitden no longer talks to any gateway except its own. Nothing new goes online, and Kitden reads no new kind of file: it now reads more of Claude Code's settings files (user, project and local) and a trusted project's `.codex/config.toml`, which are settings files it already reads. See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.10.0/PRIVACY.md).

Limits:

- A secret of about 1,972 to 2,019 bytes was stored whole before and is now refused on macOS. The limit is about 1,970 bytes. The Keychain tests ran on one GitHub macOS runner image; other macOS versions are not checked.
- Claude Code approvals from managed settings, from `--settings`, or from a git-tracked local file that needs trust are not read.
- A real browser sign-in longer than the limit is tested with a stand-in only.
- The removal of outside gateways was not tried by hand in a browser.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.10.0/docs/development.md#check-before-a-release) have not all been completed.
