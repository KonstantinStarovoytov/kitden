# Kitden 0.12.0 — new: set the skill list limit by dragging a line; turn off built-in skills and plugins

Kitden 0.12.0 lets you give Claude Code's and Codex's skill list more room. When skills showed only a name, you drag the limit line on the Context page's bar, see what each step gives, and set it with a preview, a backup and Undo. Most Claude Code skills now have a switch too, including 13 built-in ones, and a plugin's skill can turn its whole plugin off. The skill counts are also more exact.

## New

- **Set the skill list limit by dragging the limit line.** On the Context page, the limit line on the skill list's bar has a handle. Drag it, or use the arrow keys, to move from share to share: 1%, 1.1%, 1.2%, 1.3%, 1.4%, 1.5%, 1.7%, 2%, 2.5%, 3%, 3.5% and 4% of the context window. A note says what each step gives, such as "1.5% · all 20 fit · about 650 more characters per chat", and the line snaps to the first share where every description fits. Let go to add the change to the tray. Apply writes `skillListingBudgetFraction` in `~/.claude/settings.json` for all projects, with a backup and Undo. **Back to 1%** takes it out. When your settings already hold a higher share, you can drag down to any place below it. Click the line's label for the details: the limit now, the suggested share and the cost. Codex's card has the same line in steps of 500 tokens up to 10,000, and writes `[skills] max_context_tokens` in `config.toml`. After Apply the page says the limit changed and that your next chat shows the real list. Kitden does not offer it when `SLASH_COMMAND_TOOL_CHAR_BUDGET` is set, when a project's own settings set the share, or when even 4% (for Codex, 10,000 tokens) would not fit every description. When Kitden cannot replay the last chat's list, which is common with a newer Claude Code, it counts what all descriptions need and says so. See "Upgrade and limits". ([#189](https://github.com/KonstantinStarovoytov/kitden/pull/189), [#190](https://github.com/KonstantinStarovoytov/kitden/pull/190), [#191](https://github.com/KonstantinStarovoytov/kitden/pull/191), [#195](https://github.com/KonstantinStarovoytov/kitden/pull/195)) @KonstantinStarovoytov, ([966605b](https://github.com/KonstantinStarovoytov/kitden/commit/966605b)) Amanda Woodward
- **Turn off built-in skills and whole plugins from the Context page.** On one real setup, 15 of 92 skills had a switch. Now 52 have a control. 13 skills built into Claude Code have the same switch as your own (On, Name only, Off), for all projects. The old words "Kitden cannot turn it off" were wrong for them. The Details of a plugin's skill offer "Turn off superpowers" for the whole plugin and say what goes with it, such as "Turns off all of superpowers: 15 skills and 1 hook". Skills that are off wait under **Turned off**, where you can turn them on again. For a skill with no switch, such as one from the Claude app, the Details say where it comes from and why. The estimate stays when a skill was set to Off or Name only after the last chat. ([#193](https://github.com/KonstantinStarovoytov/kitden/pull/193)) @KonstantinStarovoytov

## Better

- **Turn a Claude Code skill off in one project beside your other skill rules.** Kitden refused this while your settings or the project's shared file already held a skill rule, and said Claude Code may not merge them. It does merge them. One preview can now hold a rule for all projects and a rule for one project, and the review names only the projects whose own rule keeps the skill on. ([#194](https://github.com/KonstantinStarovoytov/kitden/pull/194)) @KonstantinStarovoytov
- **A built-in skill counts at its real size.** `init` and `security-review` have no file, so Kitden counted each description at the longest, 1,536 characters. Their real descriptions are 59 and 71 characters. Kitden now takes the description from the newest earlier chat that sent it, and the Details say how many skills count so. On one real setup the suggested share went from 1.5% to 1.4%, and the cost from about 3,100 to about 160 more characters. The place of today also says "1.3% now · 2 of 92 show only a name" instead of "not all fit". ([#197](https://github.com/KonstantinStarovoytov/kitden/pull/197)) @KonstantinStarovoytov

## Fixed

- **A skill that Claude Code lists with its command is read right.** Claude Code lists a skill as `name (command)` when the word you type is not its name, such as `ship-local (ship)`. Kitden took it for a skill with only a name and added its line to the skill before it. Now both are read, and the command counts in the size of the list. On one real setup the size Kitden shows now equals the text in the log. ([#192](https://github.com/KonstantinStarovoytov/kitden/pull/192)) @KonstantinStarovoytov

## Upgrade and limits

Update with `uv tool upgrade kitden` or `brew upgrade kitden`. The gateway did not change, so your agents need no restart. Requires macOS or Linux.

Nothing new goes online. What Kitden writes and reads changes a little:

- When you set the skill list limit and press Apply, Kitden writes `skillListingBudgetFraction` in `~/.claude/settings.json`, or `[skills] max_context_tokens` in Codex's `config.toml`. It makes a backup first, and you can undo it.
- For a skill built into Claude Code, which has no file, Kitden reads the description an earlier chat sent, from the newest chat files (at most the 40 newest logs). It keeps none of it.
- Turning off a built-in skill or a plugin writes the same settings files as other skill and plugin switches, with the same preview, backup and Undo.

See [Privacy](https://github.com/KonstantinStarovoytov/kitden/blob/v0.12.0/PRIVACY.md).

Limits:

- Kitden has not been tried against a real Claude Code or Codex that reads the value it writes. That they honour it, and whether a running Claude Code chat or Codex needs a restart, are guesses. Restart Codex to be safe. Whether a project `.codex/config.toml` or a profile overrides the Codex key is open. The page shows the real list after your next chat.
- The built-in skills and plugin switches were checked with Claude Code 2.1.330 in print mode. The Claude app was not checked, and neither was pressing Apply on "Turn off superpowers" from this page.
- When Kitden cannot replay the last chat, the share it suggests comes from a count and may be a step higher than you need. Skills with no description Kitden can find count at the longest a description can be.
- A share in your settings that is not on the list, such as 4.5% from an earlier build or one written by hand, still works as the limit now.
- For Codex, "Back to the default" can leave an empty `[skills]` header when Kitden added the table.
- Before/after pictures of the new limit line are not in the README yet.

Kitden is still alpha: the real-client checks in [Development](https://github.com/KonstantinStarovoytov/kitden/blob/v0.12.0/docs/development.md#check-before-a-release) have not all been completed.
