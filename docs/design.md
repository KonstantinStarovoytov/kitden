# Kitden design

How the page looks and moves. `src/kitden/web/static/style.css` holds the values; this file says why.
Quiet Den + Graphite, light and dark.

**Moving to the mockup (2026-10-24).** The owner's mockup, [docs/mockup](mockup/README.md), is the
target. The [alignment plan](superpowers/plans/2026-10-24-mockup-alignment.md) moves the pages to

the code. Until then, this file describes the page as it is.

## Identity

Kitden is a calm local home for a developer's coding tools. The mark is a soft asymmetric house with an off-center arched door. The wordmark is Kitden in Inter, medium-bold, with slightly tight tracking.

Canonical asset: `src/kitden/web/static/brand/kitden.svg`. The rail and favicon reuse this file. It contains no third-party mark.

**The house is always #C85835.** Never recolor it for dark mode, use a white fallback, apply opacity, or add gradients. Use the same silhouette in both themes. Keep clear space around it. The rail renders it at 28 px; favicon has a 64-unit viewBox and a simple silhouette for small sizes.

The brand mark is fixed; functional shades adapt for text contrast. Text on the action, success and dim fills, and diff text on its tint and on the drawer, keeps at least 4.5:1 in both themes (WCAG 2.2 AA, checked 2026-10-19); `tests/unit/test_contrast.py` holds the line. Icons, grips, hollow marks and the edge of an unticked check or radio use `--lamp-off`, which fails 4.5:1 as text, so text uses `--ink-3` (`--ink-4` for the faintest). The edge of a check or radio keeps 3:1 (WCAG 1.4.11, checked 2026-10-24) on the panel, raised panel, inset, dim, canvas and selection fills in both themes, which `--lamp-off` does (so the dark one is a little lighter than the mockup's) and `--link` does not; `tests/unit/test_contrast.py` holds that line too. A switch is found by its knob (`--ink-3` on the inset track, at least 4.9:1), not by its edge. In the light theme `--ink-3` and `--ink-4` are a hair darker than the mockup's #646B79 so text keeps 4.5:1 on a selected block. Lines are solid colors: `--wire-soft` is `--wire` at 60%, and `--wire-strong` mixes 18% of the main text color into `--wire`. A map link takes `--link`; borders take a `--wire` line. Green text uses `--diff-add`, not the lamp color. Do not use the logo color for every small label. Success stays green, warnings amber and errors red, paired with text/shape. A server a client sets up on its own is joined to that client by a faint amber elbow (`--lamp-warn` at 55%): its calls skip Kitden's rules. Amber here marks a route outside the rules, not a fault. Vendor marks must retain their own permitted colors when verified; Claude, Cursor and Codex use local vendor icons (see `src/kitden/web/static/brand/clients/ATTRIBUTION.md`). Neutral monograms are used only for unknown clients or failed image loads.

## Client marks

Every client mark is the same rounded tile (24 px, radius 6, raised-panel background, thin border), so the row of clients reads as one family. The Codex and Cursor icons fill the tile and switch to the vendor's own dark version in the dark theme; the Claude glyph sits inside it with 4 px padding and works on both. The tile grows to 28 px where the client is the headline: the Clients card on Overview and the title of a detail panel. Do not tint, recolor or shrink a vendor icon to show a state; state lives in the badge next to it.

## Components

Preserve the compact information layout. Use restrained neutral panels, fine borders and the existing 6–10 px corner radii. Primary actions use the action fill. Selected navigation uses a tinted background, accent text and a brand-colored inset bar. Tabs and selected filters use the same accent family. Tables, drawer, forms, loading, toast and empty states inherit shared tokens; no page-specific blue accents. Icons are lucide 0.469.0 shapes kept as data in `static/js/icons.js`; `icon()` in `dom.js` draws them with `createElementNS`, never from markup. Add a name to that file before using it.

The shell is one framed window (1 px line, 12 px corners) on the `--out` color, with a 16 px gutter. The rail is 148 px: the wordmark, four links with icons (Overview, Library, Gateway, Changes) and a marker that glides behind the current one; at the bottom the scan time with Rescan, "Let agents read this setup" and "Appearance", which switches light and dark (its hover text names the other theme). The top bar is 66 px: the project button ("Project" and the picked name, in the accent when a project is picked), then the search with its icon. A page starts with its title (24 px), a quiet 12 px lede and, on the Gateway, the scope bar with a layers icon (all projects) or a folder icon (a project). The hint line (`setHint` in `parts.js`) sits 14 px above the bottom of the page: an info icon and a few words, hidden when a page sets none. Details open as a panel 16 px inside the window's edge. Under 900 px the rail becomes a row on top, its words hide behind the icons (a screen reader still hears them) and the top bar wraps to two rows.

Small parts (`style.css`, Controls). A button has 12 px text, a 7 px corner, a `--wire` line and the raised-panel fill; it presses to 0.97 and springs back, and on hover its line takes a light accent tint. A small button has 11 px text and is still 24 px tall; the primary button is the action color with 600 text. A pill (`.seg`) is an inset track with a `--wire` line and `--ink-3` choices, and a raised marker glides behind the pressed one (`--ink`, 500). A chip (`.chip`) is a short quiet label with a line round it; a client's mark beside its name is a `.who`. A lamp (beside words) or a mark (beside a tool) is 6 px: grey is off, green works, amber needs you, a dashed accent ring is only a preview, a grey ring works outside the gateway; a lamp that just turned on pops from 2.2 times its size. A port is the 9 px ring where a link meets a block. A switch is a 34 x 20 track with a 14 px knob inside a 24 px button: off, the knob is grey; on, it is white on the accent; while the preview loads the track is dashed on the accent tint and the knob rests half-way. A check is a 16 px box, and a radio a 14 px circle, with a `--lamp-off` line; ticked, it turns accent and the check springs in. A client's checkbox keeps its real input (for the keys and screen readers); only its box is drawn.

On Overview, an option ("Can improve") is a quiet card: `.issue.suggestion` has no warning border and a plain button, not the primary one. A card with no button (a file Kitden could not read) keeps its title and sentence in the wide column. On the Clients card a client Kitden could not read says "Could not read", never "Not installed".

Overview's notes are grouped by item: one row per name with the mark of every client it is about, and each note as a quiet flag. Flags that do not fit wrap under the name. "Same name, another source" says two entries differ; "Set up in more than one client" says the same one is set up twice.

A row that opens Details ends with a quiet › and the hidden words "Open details" (`opens()` in `parts.js`). The chevron turns accent on hover and keyboard focus; it does not move. The search box names what it searches: "Search your setup and marketplaces…". On the Gateway the search finds on the page instead: matches light up and everything else dims to 35% (links to 25%; a group caption such as "Remote" is never a match), a folded server opens to show a matching tool (a match behind "N more" shows its group whole), the same rows light in the List, and a chip in the search box says "N matches" ("1 match", "No matches"). Escape in the box clears it and leaves Details alone; finding changes no client and starts no preview. "/" focuses the search while Details sit beside the page, not while the drawer is open. Overview and Changes still send a search to the Library. The project picker is a button with a folder icon that reads "Project", the picked project's name and a chevron (`projectButton` in `parts.js` draws it everywhere). It opens a 300 px menu: "Find a project…" at the top, then "All projects" (a layers icon) with "What applies in every project", then each project (a folder icon) by folder name with "1 own rule" or "N own rules" at the right in the accent color when it has any (a folder that is gone says "Folder missing"), and no paths. The picked option sits on the accent tint with a check at its end; the option the arrow keys are on has a thin ring. The menu grows in from its top-left corner (180 ms) and fades out (140 ms); it is hidden by time, never by an animation event, and the page draws the picker again only after the fade, so a pick shows the menu closing. After a pick the name in the button rolls: the old one out, the new one in (it just changes with reduced motion). It opens with the picked project in view. Focus goes into the find box; typing narrows the projects and "All projects" stays first; Down, Up, Home and End move through the options, Enter picks one, and Escape or a click outside closes the menu (Escape gives focus back to the button). A pick opens a new history entry. A picked project that leaves the list stays picked (the menu says "No longer on the list"), while Overview, Library and Gateway say "This project is no longer on the list." and read nothing for it. Under a page head the scope bar (`scopeBar` in `parts.js`, on the Gateway first) says "Shared setup · project overrides stay separate" with All projects picked, or, in the accent color, "Project website · 2 rules differ from the shared setup" ("Project website · no rules of its own" when it has none, and "Project website · rules not known" when Kitden could not read the gateway settings). It counts only the gateway's rules, so it never says a project follows the shared setup. A review names its scope in the title ("… for all projects", "… in website"; see Review below) and an add, with All projects picked, in the lede too. A gateway's entry and a server put back in a client are adds for all projects too. In `kitden demo` a quiet "Demo" flag (`.flag.info`) follows the wordmark; its hover text says the setup is a sample in a temporary folder. The page reads `/api/about` once to know.

The address keeps the project and the selected item (`sel=<kind>:<name>`, as in `#library?kind=skill&project=a&sel=skill%3Atidy`) on every page, so Back and a copied link return to them. Arriving with a selection (an Overview card or note, Back, Forward or a link), the Library opens that row's Details once, and the Gateway opens the selected server's or tool's Details once (a tool its server no longer lists opens the server; a client or a group is found and focused in the List; on the map the block is selected as a click does, and a group opens the List there); a redraw does not open it again. A rail link opens its place fresh. An arrival never opens over a panel that is open, and a row or Details the person opens first wins.

A Details footer button never grows past the panel: long words end in "…", and the whole label stays in its hover text. A Remove names every client it reaches: "Remove from Codex and Cursor…" for a skill in a folder both read, but not a client that keeps another copy of its own; a switch names only its own client. When one client has two Remove buttons for the same scope, each names its folder by the last two parts: "Remove from Codex and Cursor (.agents/skills)…".

Details beside the page: on Gateway, Library and Changes, in a window 1024 px wide or more, Details is a 320 px column at the right with no scrim. The page makes room for it and stays usable. Escape closes it, and focus goes back to what opened it, also after the page was drawn again. In a narrower window, and on Overview, Details stays the drawer; a window that crosses 1024 px while Details is open switches between the two. A review opens in the same column. The page stays usable beside a review: while its change is written, a press that would open other Details does nothing, and a review that is only previewed is cancelled when other Details replace it, as closing it would. A Details card (`detailsCard` in `details.js`) draws, top to bottom: the kind and Close, the title with its id quiet under it, Facts (labels 86 px wide), one sentence, the actions stacked full width, and "Technical details" folded at the bottom.

## Motion


Kitden edits real settings files. Motion has one job: explain what changed and where. It never
decorates, never suggests work the page cannot see, and never shows a result before the server
has verified it. Calm beats bouncy: a tool that edits files must feel steady.

### Principles

1. **Truth first.** A success look (check, green button, flipped switch, new socket) appears
   only after the server says `verified`. A control under review shows a pending state, not
   the new state.
2. **No fake activity.** Nothing loops to suggest traffic, scanning or progress Kitden cannot
   observe. A link on a map draws once when it appears, then rests.
3. **Point, don't move.** To show where something is, light it (row glow, socket ping, lit
   rows). Layout moves only when the thing itself moves (a tile flying to its column).
4. **Errors stay.** An error is a callout that stays until the next action; focus goes back to
   the button that failed. No success animation can follow an error.
5. **Interruptible.** Every animation can be cut short; the true state is always the resting
   style, never something an animation must finish to reach.
6. **Transform and opacity.** Only these animate, with five small exceptions (the client
   counts row, a folded `<details>`, the sliding mark, a check or a map link drawing its
   stroke, a map link redrawn as its blocks move), all on small elements.

### Tokens

Defined once in `style.css`. Scripts use `CALM` from `motion.js`; the spring is CSS only.

### Conventions

- One motion per change. A change that morphs cells does not also cross-fade the page.
- A new control gets the press (`transform`), a hover colour and a visible focus ring; nothing else.
- Lists stagger, single things do not. Total stagger under 500 ms.
- A drawer has one motion: it slides in. Its blocks and diff lines are there at once. The column
  beside the page slides in the same way, and the page takes its room at once.
- Put the resting style in CSS and the animation in a class or keyframe, so a skipped animation
  still lands on the right look.
- Never read the true state from `transitionend` or `animationend`; use a timer or the data.
- New wording tests go in `tests/unit/test_page_words.py`; helper logic in a node test in `tests/frontend/` (all run with `node --test tests/frontend/*.test.mjs`).

### Accessibility

- `prefers-reduced-motion: reduce` turns every animation and transform transition off (one
  rule at the end of `style.css`); `animate()` and `transition()` return early; folds,
  flights and socket morphs just switch.
- Keyboard opens and closes the panel instantly. The Gateway List is a tree grid: each row
  says its level and whether it is open, and the arrow keys move (`gridKey()` in `dom.js`).
  Every control keeps `:focus-visible`.
- A redraw keeps keyboard focus: a tab, filter button, menu or row with a `data-focus` key (or
  a row key) gets focus back. Arrow keys, Home and End move between tabs and select (`tabKeys()`
  in `dom.js`). The review's Tab loop includes its "Show file change" summary. After a page's
  Retry, focus goes to the new Retry if the read failed again, else to the page's first control.
- Live regions: the toast is `role="status"`; errors are `role="alert"`.

### Performance

- Checked with 39 MCP servers, 6 plugins and 3 findings on one page: no long task over 50 ms
  while moving between places or applying a change.
- Animate `transform` and `opacity`; a sliding mark animates its own width and height only.
- No library, no bundler, nothing loaded at run time.

### Examples

Open a place with a shared tile:

```js
fly(tile, `client-${clientId}`);   // on the old place, right before go()
go("library", { kind });
// on the new place, while it draws:
land(columnTile, `client-${columnId}`);
```

A group with a sliding mark (the group needs `position: relative`):

```js
glide(box, box.querySelector('[aria-selected="true"]'), "library-tabs");
```

A smooth `<details>`:

```js
details.append(summary, content);
main.append(fold(details));
```
