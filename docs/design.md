# Kitden design

How the page looks and moves. `src/kitden/web/static/style.css` holds the values; this file says why.
Quiet Den + Graphite, light and dark.

**Moving to the mockup (2026-10-24).** The owner's mockup, [docs/mockup](mockup/README.md), is the
target. The [alignment plan](superpowers/plans/2026-10-24-mockup-alignment.md) moves the pages to

the code. Until then, this file describes the page as it is.

## Identity

Kitden is a calm local home for a developer's coding tools. The mark is a soft asymmetric house with an off-center arched door. The wordmark is Kitden in Inter, medium-bold, with slightly tight tracking.

Canonical asset: `src/kitden/web/static/brand/kitden.svg`. The rail and favicon reuse this file. It contains no third-party mark.

**The house is always #C85835.** Never recolor it for dark mode, use a white fallback, apply opacity, or add gradients. Use the same silhouette in both themes. Keep clear space around it. The rail renders it at 28 px; favicon has a 64-unit viewBox and a simple silhouette for small sizes.

The brand mark is fixed; functional shades adapt for text contrast. Text on the action, success and dim fills, and diff text on its tint and on the drawer, keeps at least 4.5:1 in both themes (WCAG 2.2 AA, checked 2026-10-19); `tests/unit/test_contrast.py` holds the line. Icons, grips, hollow marks and the edge of an unticked check or radio use `--lamp-off`, which fails 4.5:1 as text, so text uses `--ink-3` (`--ink-4` for the faintest). The edge of a check or radio keeps 3:1 (WCAG 1.4.11, checked 2026-10-24) on the panel, raised panel, inset, dim, canvas and selection fills in both themes, which `--lamp-off` does (so the dark one is a little lighter than the mockup's) and `--link` does not; `tests/unit/test_contrast.py` holds that line too. A switch is found by its knob (`--ink-3` on the inset track, at least 4.9:1), not by its edge. In the light theme `--ink-3` and `--ink-4` are a hair darker than the mockup's #646B79 so text keeps 4.5:1 on a selected block. Lines are solid colors: `--wire-soft` is `--wire` at 60%, and `--wire-strong` mixes 18% of the main text color into `--wire`. A map link takes `--link`; borders take a `--wire` line. Green text uses `--diff-add`, not the lamp color. Do not use the logo color for every small label. Success stays green, warnings amber and errors red, paired with text/shape. A server a client sets up on its own is joined to that client by a grey dotted line at right angles (`--lamp-off` at 80%), amber under the pointer: its calls skip Kitden's rules. Amber here marks a route outside the rules, not a fault. Vendor marks must retain their own permitted colors when verified; Claude, Cursor and Codex use local vendor icons (see `src/kitden/web/static/brand/clients/ATTRIBUTION.md`). Neutral monograms are used only for unknown clients or failed image loads.

## Client marks

Every client mark is the same rounded tile (24 px, radius 6, raised-panel background, thin border), so the row of clients reads as one family. The Codex and Cursor icons fill the tile and switch to the vendor's own dark version in the dark theme; the Claude glyph sits inside it with 4 px padding and works on both. The tile grows to 28 px where the client is the headline: the Clients card on Overview and the title of a detail panel. Do not tint, recolor or shrink a vendor icon to show a state; state lives in the badge next to it.

## Components

Preserve the compact information layout. Use restrained neutral panels, fine borders and the existing 6–10 px corner radii. Primary actions use the action fill. Selected navigation uses a tinted background, accent text and a brand-colored inset bar. Tabs and selected filters use the same accent family. Tables, drawer, forms, loading, toast and empty states inherit shared tokens; no page-specific blue accents. Icons are lucide 0.469.0 shapes kept as data in `static/js/icons.js`; `icon()` in `dom.js` draws them with `createElementNS`, never from markup. Add a name to that file before using it.

The shell is one framed window (1 px line, 12 px corners) on the `--out` color, with a 16 px gutter. The rail is 148 px: the wordmark, four links with icons (Overview, Library, Gateway, Changes) and a marker that glides behind the current one; at the bottom the scan time with Rescan, "Let agents read this setup" and "Appearance", which switches light and dark (its hover text names the other theme). The top bar is 66 px: the project button ("Project" and the picked name, in the accent when a project is picked), then the search with its icon. A page is at most 1180 px wide; the Gateway page has no limit, so its Map | List pill sits at the right edge. A page starts with its title (24 px), a quiet 12 px lede and, on the Gateway, the scope bar with a layers icon (all projects) or a folder icon (a project). The hint line (`setHint` in `parts.js`) sits 14 px above the bottom of the page: an info icon and a few words, hidden when a page sets none. Details open as a panel 16 px inside the window's edge. Under 900 px the rail becomes a row on top, its words hide behind the icons (a screen reader still hears them) and the top bar wraps to two rows.

Small parts (`style.css`, Controls). A button has 12 px text, a 7 px corner, a `--wire` line and the raised-panel fill; it presses to 0.97 and springs back, and on hover its line takes a light accent tint. A small button has 11 px text and is still 24 px tall; the primary button is the action color with 600 text. A pill (`.seg`) is an inset track with a `--wire` line and `--ink-3` choices, and a raised marker glides behind the pressed one (`--ink`, 500). A chip (`.chip`) is a short quiet label with a line round it; a client's mark beside its name is a `.who`. A lamp (beside words) or a mark (beside a tool) is 6 px: grey is off, green works, amber needs you, a dashed accent ring is only a preview, a grey ring works outside the gateway; on the Gateway map a lamp that turns on or off fades to its new color in 400 ms and pops from 2.2 times its size (a client's from 2.4, a tool's mark from 1.9; `--pop` in `style.css`), by Web Animations in `map-view.js`; other lamps just change. A port is the 9 px ring where a link meets a block; it is grey on a server outside the gateway. A switch is a 34 x 20 track with a 14 px knob inside a 24 px button: off, the knob is grey; on, it is white on the accent; while its change waits in the tray the track is dashed on the accent tint and the knob rests half-way. A check is a 16 px box, and a radio a 14 px circle, with a `--lamp-off` line; ticked, it turns accent and the check springs in. A client's checkbox keeps its real input (for the keys and screen readers); only its box is drawn.

On Overview, an option ("Can improve") is a quiet card: `.issue.suggestion` has no warning border and a plain button, not the primary one. A card with no button (a file Kitden could not read) keeps its title and sentence in the wide column. On the Clients card a client Kitden could not read says "Could not read", never "Not installed".

Overview's notes are grouped by item: one row per name with the mark of every client it is about, and each note as a quiet flag. Flags that do not fit wrap under the name. "Same name, another source" says two entries differ; "Set up in more than one client" says the same one is set up twice.

A row that opens Details ends with a quiet › and the hidden words "Open details" (`opens()` in `parts.js`). The chevron turns accent on hover and keyboard focus; it does not move. The search box names what it searches: "Search your setup and marketplaces…". On the Gateway the search finds on the page instead: matches light up and everything else dims to 35% (links to 25%; a group caption such as "Remote" is never a match), a folded server opens to show a matching tool (a match behind "N more" shows its group whole), the same rows light in the List, and a chip in the search box says "N matches" ("1 match", "No matches"). Escape in the box clears it and leaves Details alone; finding changes no client and starts no preview. "/" focuses the search while Details sit beside the page, not while the drawer is open. Overview and Changes still send a search to the Library. The project picker is a button with a folder icon that reads "Project", the picked project's name and a chevron (`projectButton` in `parts.js` draws it everywhere). It opens a 300 px menu: "Find a project…" at the top, then "All projects" (a layers icon) with "What applies in every project", then each project (a folder icon) by folder name with "1 own rule" or "N own rules" at the right in the accent color when it has any (a folder that is gone says "Folder missing"), and no paths. The picked option sits on the accent tint with a check at its end; the option the arrow keys are on has a thin ring. The menu grows in from its top-left corner (180 ms) and fades out (140 ms); it is hidden by time, never by an animation event, and the page draws the picker again only after the fade, so a pick shows the menu closing. After a pick the name in the button rolls: the old one out, the new one in (it just changes with reduced motion). It opens with the picked project in view. Focus goes into the find box; typing narrows the projects and "All projects" stays first; Down, Up, Home and End move through the options, Enter picks one, and Escape or a click outside closes the menu (Escape gives focus back to the button). A pick opens a new history entry. A picked project that leaves the list stays picked (the menu says "No longer on the list"), while Overview, Library and Gateway say "This project is no longer on the list." and read nothing for it. Under a page head the scope bar (`scopeBar` in `parts.js`, on the Gateway first) says "Shared setup · project overrides stay separate" with All projects picked, or, in the accent color, "Project website · 2 rules differ from the shared setup" ("Project website · no rules of its own" when it has none, and "Project website · rules not known" when Kitden could not read the gateway settings). It counts only the gateway's rules, so it never says a project follows the shared setup. A review names its scope in the title ("… for all projects", "… in website"; see Review below) and an add, with All projects picked, in the lede too. A gateway's entry and a server put back in a client are adds for all projects too. In `kitden demo` a quiet "Demo" flag (`.flag.info`) follows the wordmark; its hover text says the setup is a sample in a temporary folder. The page reads `/api/about` once to know.

The address keeps the project and the selected item (`sel=<kind>:<name>`, as in `#library?kind=skill&project=a&sel=skill%3Atidy`) on every page, so Back and a copied link return to them. Arriving with a selection (an Overview card or note, Back, Forward or a link), the Library opens that row's Details once, and the Gateway opens the selected server's or tool's Details once (a tool its server no longer lists opens the server; a client or a group is found and focused in the List; on the map the block is selected as a click does, and a group opens the List there); a redraw does not open it again. A rail link opens its place fresh. An arrival never opens over a panel that is open, and a row or Details the person opens first wins.

A Details footer button never grows past the panel: long words end in "…", and the whole label stays in its hover text. A Remove names every client it reaches: "Remove from Codex and Cursor…" for a skill in a folder both read, but not a client that keeps another copy of its own; a switch names only its own client. When one client has two Remove buttons for the same scope, each names its folder by the last two parts: "Remove from Codex and Cursor (.agents/skills)…".

Details beside the page: on Gateway, Library and Changes, in a window 1024 px wide or more, Details float over the right of the page, as in the mockup: 320 px wide, 22 px from the content's right, 46 px above its bottom (level with the tray's bar), from the top of what the page shows under its head (the map, a list), with 10 px corners, padding 18, the panel fill, a line and the shadow. Its parts stack 16 px apart and the whole panel scrolls. There is no scrim: the page stays usable, and the dock stays above the panel. When the page scrolls, the panel's top follows the stage and stops 22 px under the top bar (read at most once a frame). The Gateway map keeps its width: while the panel covers part of it the map can scroll sideways, and a block under the panel scrolls left into view beside it when it is selected or takes keyboard focus. A list or a table (Library, Changes, the Gateway List) keeps room on its right for the panel instead, so no control and no focus sits under it. While the panel goes it takes no press and no Tab. Escape and Close close it, and focus goes back to what opened it, also after the page was drawn again. In a narrower window, and on Overview, Details stays the modal drawer with its scrim and focus loop; a window that crosses 1024 px while Details is open switches between the two. A row's review ("Show changes") and Add missing's list open in the same panel. Nothing in Details writes: the tray holds every change, so closing Details, Escape or other Details never take a row out of it or cancel anything on the server. A Details card (`detailsCard` in `details.js`) draws, top to bottom: the kind and Close, the title with its id quiet under it, Facts (labels 86 px wide), one sentence, the actions stacked full width, and "Technical details" folded at the bottom.

An Add missing row's review shows its ticks: a changed tick adds the row again with the new choice (it keeps its place in the bar while it is asked), and with none ticked it says "Choose at least one item." and the row stays. × takes one row out and the rest are previewed again; Cancel and Cancel all forget the preview. All rows are one change on the server, so Apply all writes everything or nothing and the toast offers one Undo: "Applied 3 changes" with "Undo all"; one change says its own words with "Undo".

While Apply runs, Cancel and every × are off, Apply keeps its place and counts the steps ("Applying 2 of 5"), the line names the clients being written, and the first row spins until the whole change is verified. Then every row checks together, Apply turns green and says "Applied" ("All applied"), and a moment later the page reads everything again, the bar leaves and the toast takes its place. An end that is not verified stays in the bar with an accent edge and a shake, and focus goes to the button that comes next. "Nothing was changed" is said only when it is true: stale ("Settings changed since this preview.") or every file put back ("The change did not check out. Kitden put the files back."). It offers "Try again", a fresh preview of the same rows. Otherwise the head says "Not everything was put back" or "Could not confirm the result", the line says "Check Changes before trying again.", and "Open Changes" takes Apply's place. A refused add never joins: the reason takes the bar's line, in the accent color, until the next action, and a bar that is already shown shakes. A reason that names a file names it by its base name ("mcp.json"); the full words stay on Changes. A first add that is refused (no bar before) comes in with the bar's entrance, with no shake (one motion per change), and shows "Could not prepare this change", the reason and Close; rows that cannot be previewed again say "Could not prepare the preview" and offer Try again. After each rescan, and after an Undo, the tray asks the server whether its files changed since the preview (the same check Apply makes); when they did, the line says so and Apply becomes "Preview again", a fresh preview of the same rows. The Gateway-map sentence follows the place: the page draws the bar again after a place change, with no new entrance.

## Motion


Kitden edits real settings files. Motion has one job: explain what changed and where. It never
decorates, never suggests work the page cannot see, and never shows a result before the server
has verified it. Calm beats bouncy: a tool that edits files must feel steady.

### Principles

1. **Truth first.** A success look (check, green button, flipped switch, new socket) appears
   only after the server says `verified`. A control whose change waits in the tray shows a
   pending state, not the new state.
2. **No fake activity.** Nothing loops to suggest traffic, scanning or progress Kitden cannot
   observe. A link on a map moves only when it comes, goes or changes look, then rests.
3. **Point, don't move.** To show where something is, light it (row glow, socket ping, lit
   rows). Layout moves only when the thing itself moves (a tile flying to its column).
4. **Errors stay.** An error is a callout that stays until the next action; focus goes back to
   the button that failed. No success animation can follow an error.
5. **Interruptible.** Every animation can be cut short; the true state is always the resting
   style, never something an animation must finish to reach.
6. **Transform and opacity.** Only these animate, with nine small exceptions (the client
   counts row, a folded `<details>`, the sliding mark, a check or a map link drawing, undrawing or blending its
   stroke, a map link redrawn as its blocks move, the `filter` that dims a map block off the lit path,
   the `stroke`, `stroke-width` and `stroke-opacity` of a map link as its look changes, the width and height
   of the tray bar as rows join or leave, the color of a lamp on the map), all on small elements.

### Conventions

- One motion per change. A change that morphs cells does not also cross-fade the page.
- A new control gets the press (`transform`), a hover colour and a visible focus ring; nothing else.
- Lists stagger, single things do not. Total stagger under 500 ms. Two map waves have their own
  rule: the entrance fits in 440 ms however many blocks there are, and a server's unfold has no
  cap (15 ms between its tools, however many it has).
- A drawer has one motion: it slides in. Its blocks and diff lines are there at once. The floating
  panel has one too: it fades in from the right, a little smaller, and the map never moves for it.
  What it shows next comes through its skeleton (another block) or a step (inside one panel); the
  drawer shows neither.
- Put the resting style in CSS and the animation in a class or keyframe, so a skipped animation
  still lands on the right look.
- Never read the true state from `transitionend` or `animationend`; use a timer or the data.
- New wording tests go in `tests/unit/test_page_words.py`; helper logic in a node test in `tests/frontend/` (all run with `node --test tests/frontend/*.test.mjs`).

### Accessibility

- `prefers-reduced-motion: reduce` turns every animation and transform transition off (one
  rule at the end of `style.css`); `animate()` and `transition()` return early; folds,
  flights and socket morphs just switch.
- Keyboard opens and closes the panel instantly. The Gateway List is a tree grid: each row
  says its level and whether it is open, and the arrow keys move (`gridKey()` in `dom.js`).
  Every control keeps `:focus-visible`.
- A redraw keeps keyboard focus: a tab, filter button, menu or row with a `data-focus` key (or
  a row key) gets focus back. Arrow keys, Home and End move between tabs and select (`tabKeys()`
  in `dom.js`). The review's Tab loop includes its "Show file change" summary. After a page's
  Retry, focus goes to the new Retry if the read failed again, else to the page's first control.
- A link the page can act on is a button after the blocks, named "<from> to <to>": keyboard focus
  (`:focus-visible`; a mouse click does not) gives it the hover look and its ×, Enter or Space
  opens it once, Delete does what its × does. The group of these buttons is hidden from a screen
  reader while it holds none.
- Live regions: the toast's words, and each change that joins or leaves the tray, go to the page's quiet live region (`#said`, always there; the toast itself is not one, so nothing is said twice); errors are `role="alert"`.

### Performance

- Checked with 39 MCP servers, 6 plugins and 3 findings on one page: no long task over 50 ms
  while moving between places or applying a change.
- Animate `transform` and `opacity`; a sliding mark animates its own width and height only.
- No library, no bundler, nothing loaded at run time.

### Examples

Open a place with a shared tile:

```js
fly(tile, `client-${clientId}`);   // on the old place, right before go()
go("library", { kind });
// on the new place, while it draws:
land(columnTile, `client-${columnId}`);
```

A group with a sliding mark (the group needs `position: relative`):

```js
glide(box, box.querySelector('[aria-selected="true"]'), "library-tabs");
```

A smooth `<details>`:

```js
details.append(summary, content);
main.append(fold(details));
```
