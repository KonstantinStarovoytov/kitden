# Working on Kitden

- Talk to the owner in simple Russian until asked otherwise.
- Write code, comments, UI text, and documentation in simple English.
- Prefer clear diagrams and comparison tables when they help explain a decision.
- Follow the [project constitution](.specify/memory/constitution.md).
- Read the [project brief](docs/project-brief.md) before proposing scope changes.
- Use the installed Spec Kit skills in `.agents/skills/` for feature development.
- Keep research, proposed decisions, and confirmed requirements clearly labeled.
- Verify changing technical claims against primary sources. Record the review date.
- Do not assume a technology stack has been chosen. Research recommendations are proposals.
- Do not add implementation code during a research-only task.
- Keep work proportional to a self-hosted project for one owner and a small team.
- Continue authorized work without repeated confirmation. Ask only when a missing decision matters.
